\# Bash скриптинг

## Шаблон правильного скрипта

Каждый production-ready bash скрипт должен начинаться с:

```bash
#!/usr/bin/env bash
set -euo pipefail

# Ваш код
```

---

## set — управление атрибутами оболочки

### Основные опции

| Команда | Описание |
|---------|----------|
| `set -e` | Остановить скрипт при ошибке любой команды |
| `set -u` | Ошибка при использовании неопределённой переменной |
| `set -x` | Debug-режим: вывод каждой команды перед выполнением |
| `set -o pipefail` | Ошибка пайплайна = ошибка первой упавшей команды |
| `set +e` | Отключить флаг `-e` (игнорировать ошибки дальше) |

### Полная строка и её смысл

```bash
set -euo pipefail
```

- `-e` — скрипт умирает при первой ошибке
- `-u` — скрипт умирает, если переменная не объявлена (`$UNDEFINED_VAR` → ошибка)
- `-o pipefail` — `cmd1 | cmd2 | cmd3` — если cmd1 упала, весь пайплайн считается упавшим

### Как обработать ошибку в конкретной команде

```bash
# Вариант 1: || true — проигнорировать ошибку
risky_command || true

# Вариант 2: временно отключить set -e
set +e
risky_command
exit_code=$?
set -e

if [ $exit_code -ne 0 ]; then
  echo "Команда завершилась с кодом $exit_code"
fi

# Вариант 3: обработать через if
if ! risky_command; then
  echo "Ошибка, но продолжаем"
fi
```

## Переменные

### Объявление переменных

```bash
# Локальная переменная (только текущий shell-процесс)
VAR="value"

# Экспортированная переменная (доступна дочерним процессам)
export VAR="value"

# Переменная только для чтения
readonly VAR="value"

# Локальная внутри функции
function foo() {
  local VAR="value"
}
```

### Разница export vs без export

Представь: твой скрипт — это комната. Ты написал на доске `VAR=hello`. Это видно только в этой комнате.

Когда скрипт запускает другую команду (например `bash`, `python`, `curl`) — это новая комната. Доска туда не передаётся. Дочерний процесс про `VAR` ничего не знает.

`export` — это как положить переменную в конверт и передать в новую комнату. Дочерний процесс её получит.

```bash
# Без export — дочерний процесс не видит
VAR="hello"
bash -c 'echo $VAR'      # (пусто)

# С export — видит
export VAR="hello"
bash -c 'echo $VAR'      # hello
```

Важно: передача **односторонняя**. Дочерний процесс получает копию. Если он изменит `VAR` — родитель об этом не узнает.

```bash
export VAR="hello"
bash -c 'VAR="changed"; echo $VAR'   # changed (внутри дочернего)
echo $VAR                             # hello (родитель не изменился)
```

### Специальные переменные

| Переменная | Описание |
|-----------|----------|
| `$0` | Имя скрипта |
| `$1`, `$2`, ... | Позиционные аргументы |
| `$@` | Все аргументы как отдельные слова |
| `$*` | Все аргументы как одно слово |
| `$#` | Количество аргументов |
| `$?` | Код возврата последней команды |
| `$$` | PID текущего процесса |
| `$!` | PID последнего фонового процесса |

### `$@` vs `$*`

```bash
#!/bin/bash
# При вызове: ./script.sh "arg 1" "arg 2"

for arg in "$@"; do echo "$arg"; done
# arg 1
# arg 2  (каждый аргумент отдельно)

for arg in "$*"; do echo "$arg"; done
# arg 1 arg 2  (все в одной строке)
```

> Почти всегда используйте `"$@"`.

### PATH

`PATH` — переменная окружения, список директорий для поиска исполняемых файлов.

```bash
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/local/sbin

# Добавить директорию
export PATH="$PATH:/opt/myapp/bin"

# Где находится исполняемый файл
which python3
type -a python3
```

## Перенаправление ввода/вывода

### Стандартные потоки

- `0` — stdin (ввод)
- `1` — stdout (вывод)
- `2` — stderr (ошибки)

### Основные операторы

```bash
cmd > file           # stdout → файл (перезапись)
cmd >> file          # stdout → файл (добавление)
cmd < file           # stdin ← файл
cmd 2> file          # stderr → файл
cmd 2>&1             # stderr → туда, куда идёт stdout
cmd > file 2>&1      # оба потока → файл
cmd &> file          # то же самое (bash)
cmd > /dev/null 2>&1 # выбросить всё

# Только stderr на экран, stdout в /dev/null:
cmd 2>&1 >/dev/null | grep ERROR
```

### Порядок важен!

Представь что у каждого потока есть **труба**, которая куда-то ведёт. Перенаправление — это момент когда ты **подключаешь трубу** к новому месту. Важно: труба подключается к тому месту, куда **в этот момент** ведёт другая труба, а не куда она будет вести потом.

```bash
cmd 2>&1 >/dev/null
```

Читаем слева направо:
1. `2>&1` — труба stderr подключается туда, куда **сейчас** ведёт stdout. Сейчас stdout = экран. Значит stderr → экран.
2. `>/dev/null` — труба stdout переключается на /dev/null. Но stderr уже подключён к экрану — он не меняется.

Итог: **stderr на экране, stdout выброшен** ✓

```bash
cmd >/dev/null 2>&1
```

Читаем слева направо:
1. `>/dev/null` — труба stdout → /dev/null.
2. `2>&1` — труба stderr подключается туда, куда **сейчас** ведёт stdout. Сейчас stdout = /dev/null. Значит stderr → /dev/null.

Итог: **оба потока выброшены**

```bash
# Частый случай: показать только ошибки, скрыть нормальный вывод
cmd 2>&1 >/dev/null | grep ERROR

# Выбросить всё
cmd >/dev/null 2>&1
```

> Правило: `2>&1` означает "stderr туда же, куда stdout **прямо сейчас**". Порядок записи меняет результат.

### Pipe (|)

```bash
cmd1 | cmd2          # stdout cmd1 → stdin cmd2
cmd1 |& cmd2         # stdout + stderr cmd1 → stdin cmd2 (bash)

# С pipefail: если cmd1 упала — весь пайплайн упал
set -o pipefail
cat nonexistent | grep pattern   # выйдет с ошибкой
```

## Трюк с ls >a 2>b

```bash
mkdir /tmp/abc && cd /tmp/abc
ls >a 2>b
cat a
```

**Порядок обработки справа налево:**
1. Создаётся файл `b` (для stderr)
2. Создаётся файл `a` (для stdout)
3. `ls` видит в директории файлы `a` и `b`
4. Выводит их в файл `a`

Результат `cat a`:
```
a
b
```

## Условия и циклы

### Условия

```bash
# Числа
if [ "$a" -eq "$b" ]; then ...    # равно
if [ "$a" -ne "$b" ]; then ...    # не равно
if [ "$a" -lt "$b" ]; then ...    # меньше
if [ "$a" -gt "$b" ]; then ...    # больше

# Строки
if [ "$s" = "hello" ]; then ...   # равно
if [ -z "$s" ]; then ...          # пустая строка
if [ -n "$s" ]; then ...          # непустая строка

# Файлы
if [ -f "$f" ]; then ...          # существует и файл
if [ -d "$d" ]; then ...          # существует и директория
if [ -e "$f" ]; then ...          # существует
if [ -r "$f" ]; then ...          # доступен для чтения
if [ -x "$f" ]; then ...          # исполняемый

# Двойные скобки (bash) — лучше для числовых выражений
if (( a > b )); then ...
if [[ "$s" =~ ^[0-9]+$ ]]; then ...  # regex
```

### Циклы

```bash
# For по списку
for i in 1 2 3; do echo $i; done

# For по аргументам
for arg in "$@"; do
  echo "$arg"
done

# C-style for
for (( i=0; i<10; i++ )); do
  echo $i
done

# While
while [ "$count" -lt 10 ]; do
  (( count++ ))
done

# Until
until ping -c1 host &>/dev/null; do
  sleep 5
done
```

## Полезные конструкции

```bash
# Значение по умолчанию
VAR="${1:-default_value}"

# Проверка что переменная задана, иначе ошибка
VAR="${REQUIRED_VAR:?Variable REQUIRED_VAR is not set}"

# Подстановка команды
DATE=$(date +%Y-%m-%d)
FILES=$(ls /tmp/*.log 2>/dev/null)

# Арифметика
result=$(( 2 + 2 ))
(( count++ ))

# Heredoc
cat <<EOF > /etc/config
param1=value1
param2=value2
EOF

# Trap — перехват сигналов и выхода
trap 'echo "Script interrupted"; exit 1' INT TERM
trap 'cleanup_function' EXIT
```

## Отладка скриптов

```bash
# Запустить в debug-режиме
bash -x script.sh

# Включить внутри скрипта
set -x
some_command
set +x   # выключить

# Проверить синтаксис без выполнения
bash -n script.sh

# shellcheck — статический анализатор
shellcheck script.sh
```

## Системные вызовы (syscall)

Bash-команды в конечном счёте делают системные вызовы к ядру:

| Syscall | Описание | Пример |
|---------|----------|--------|
| `open` | Открыть файл | `cat file` |
| `read` | Читать из файла/FD | Чтение stdin |
| `write` | Писать в файл/FD | `echo` |
| `close` | Закрыть дескриптор | Конец команды |
| `fork` | Создать дочерний процесс | Запуск команды |
| `exec` | Заменить процесс программой | После fork |
| `wait` | Ждать завершения дочернего | `;` между командами |
| `exit` | Завершить процесс | `exit 0` |
| `kill` | Отправить сигнал процессу | `kill PID` |

```bash
# Посмотреть системные вызовы команды
strace -e trace=open,read,write ls /tmp
```
