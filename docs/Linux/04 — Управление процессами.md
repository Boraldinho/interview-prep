# Управление процессами в Linux

## Что такое процесс

**Процесс** — запущенная программа с выделенными ресурсами: адресным пространством, файловыми дескрипторами, памятью, идентификаторами.

### Ключевые идентификаторы

| Идентификатор | Описание |
|---------------|----------|
| `PID` | Process ID — уникальный номер процесса |
| `PPID` | Parent PID — PID родительского процесса |
| `UID/GID` | Пользователь и группа-владелец |
| `PGID` | Process Group ID |
| `SID` | Session ID |

---

## Состояния процессов

Процесс всегда находится в одном из состояний:

| Символ | Название | Описание |
|--------|----------|----------|
| `R` | Running / Runnable | Выполняется или готов к выполнению |
| `S` | Interruptible sleep | Ждёт событие (например, ввод с клавиатуры) |
| `D` | Uninterruptible sleep | Ждёт I/O (диск/сеть), **нельзя прервать сигналом** |
| `T` | Stopped | Остановлен сигналом SIGSTOP или под отладчиком |
| `Z` | Zombie | Завершился, но ещё в таблице процессов |
| `W` | Paging | Процесс выгружен на диск (устарело, ядро < 2.6) |

### Дополнительные флаги (второй символ)

| Символ | Описание |
|--------|----------|
| `<` | Высокий приоритет (nice < 0) |
| `N` | Низкий приоритет (nice > 0) |
| `L` | Страницы заблокированы в памяти |
| `s` | Лидер сессии |
| `l` | Многопоточный процесс |
| `+` | Находится в foreground группе |

### Состояние D (Uninterruptible sleep)

Процесс в состоянии `D` **нельзя убить** даже `kill -9`. Он ждёт ответа от подсистемы I/O (обычно диск или NFS). Если дисков нет проблем — выйдет сам. Если завис — нужно разбираться с хранилищем.

```bash
ps aux | grep ' D '    # найти D-процессы
iotop                  # посмотреть что грузит диск
```

## Сигналы

**Сигнал** — асинхронное уведомление процессу о наступлении события. Основной механизм межпроцессного взаимодействия.

### Основные сигналы POSIX

| Сигнал | Код | Описание |
|--------|-----|----------|
| `SIGHUP` | 1 | Закрытие терминала; демоны перечитывают конфиг |
| `SIGINT` | 2 | Прерывание (Ctrl+C) |
| `SIGQUIT` | 3 | Выход с дампом (Ctrl+\\) |
| `SIGKILL` | 9 | **Безусловное уничтожение** (нельзя перехватить) |
| `SIGTERM` | 15 | **Мягкое завершение** (можно перехватить, по умолчанию для kill) |
| `SIGSTOP` | 19/23 | Остановка (нельзя перехватить) |
| `SIGCONT` | 18 | Продолжить остановленный процесс |
| `SIGCHLD` | 17 | Дочерний процесс завершился |
| `SIGUSR1/2` | 10/12 | Пользовательские сигналы |

### SIGTERM (15) vs SIGKILL (9)

| | SIGTERM (15) | SIGKILL (9) |
|-|-------------|-------------|
| Перехватить? | Да | Нет |
| Поведение | Процесс может сохранить состояние и корректно завершиться | Немедленное уничтожение ядром |
| Когда использовать | Всегда сначала | Если SIGTERM не помог |

```bash
kill PID           # SIGTERM (15) — мягкое завершение
kill -15 PID       # то же самое
kill -9 PID        # SIGKILL — безусловно
kill -TERM PID     # по имени сигнала

# Отправить сигнал по имени
kill -HUP PID      # перечитать конфиг (nginx, sshd)
kill -STOP PID     # приостановить
kill -CONT PID     # продолжить

# Убить все процессы по имени
pkill nginx
killall nginx

# Сигнал группе процессов
kill -TERM -PGID
```

## Zombie-процессы

**Зомби (Z)** — процесс завершился (`exit()`), но его запись в таблице процессов не удалена, потому что родительский процесс ещё не считал код возврата (`wait()`).

### Жизненный цикл

```
Родитель → fork() → Дочерний процесс
                         ↓ exit()
                    Состояние Z (zombie)
                         ↓
Родитель → wait()  → Запись удалена
```

### Проблема зомби

- Зомби **не потребляют CPU и память** (только запись в таблице процессов)
- PID занят
- Много зомби → исчерпание PID (редко)

### Как найти зомби

```bash
ps aux | grep ' Z '
ps ajx | grep -w Z
top    # столбец STAT = Z
```

### Как убить зомби

Зомби нельзя убить напрямую (`kill -9` не работает). Нужно найти и убить/перезапустить **родительский процесс**:

```bash
# Найти родителя зомби
ps -o ppid= -p ZOMBIE_PID

# Отправить SIGCHLD родителю (заставить считать статус)
kill -SIGCHLD PARENT_PID

# Если не помогло — убить родителя
kill -9 PARENT_PID
```

## Процесс-сирота (Orphan)

**Сирота** — процесс, чей родитель завершился раньше него. Такой процесс "усыновляет" `init` (PID 1) или `systemd`.

```
PPID сироты = 1  (или субреапер)
```

**Отличие от зомби:**
- Сирота **активен** и потребляет ресурсы
- Зомби **неактивен**, только запись в таблице

```bash
# Найти сирот (PPID = 1, но не системные процессы)
ps -eo pid,ppid,cmd | awk '$2 == 1 && $1 != 1'
```

## Команды для работы с процессами

### Просмотр процессов

```bash
ps aux                        # все процессы, BSD-стиль
ps -ef                        # все процессы, UNIX-стиль
ps -eo pid,ppid,stat,cmd      # выбрать нужные столбцы
pstree                        # дерево процессов
pstree -p PID                 # дерево от конкретного процесса

# Найти процесс по имени
pgrep nginx
pgrep -a nginx                # показать команду
ps aux | grep nginx
```

### Приоритет (nice)

Диапазон от **-20** (максимальный приоритет) до **+19** (минимальный).

```bash
nice -n 10 command           # запустить с nice=10
renice -n 5 -p PID           # изменить nice запущенного процесса
renice -n -5 -p PID          # повысить приоритет (нужен root)
```

### Фоновые процессы

```bash
command &                    # запустить в фоне
jobs                         # список фоновых задач
fg %1                        # вернуть задачу 1 на передний план
bg %1                        # отправить задачу 1 в фон
Ctrl+Z                       # приостановить текущий процесс

# Отвязать от терминала
nohup command &
disown %1                    # отвязать от shell без nohup
```

## Системные вызовы процессов

```bash
# Трассировка системных вызовов
strace -p PID              # attach к запущенному процессу
strace command             # запустить и трассировать

# Популярные syscalls процессов:
# fork()   — создать дочерний процесс (копию родителя)
# exec()   — заменить образ процесса новой программой
# exit()   — завершить процесс
# wait()   — ждать завершения дочернего процесса
# kill()   — отправить сигнал процессу
# getpid() — получить свой PID
```

## systemd и управление сервисами

```bash
# Управление сервисами
systemctl start nginx
systemctl stop nginx
systemctl restart nginx
systemctl reload nginx       # SIGHUP — перечитать конфиг

# Статус и логи
systemctl status nginx
journalctl -u nginx -f       # tail логов сервиса
journalctl -u nginx --since "1 hour ago"

# Автозапуск
systemctl enable nginx
systemctl disable nginx

# Просмотр зависимостей
systemctl list-dependencies nginx
systemctl list-units --state=failed
```

### Unit-файл: шаблон

```ini
[Unit]
Description=My Service
After=network.target

[Service]
Type=simple
User=myuser
ExecStart=/usr/bin/myapp --config /etc/myapp.conf
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
```
