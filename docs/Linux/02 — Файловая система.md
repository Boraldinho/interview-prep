# Файловая система Linux

## Типы файлов в Linux

В Unix-like системах **всё является файлом**. Типы файлов:

| Символ в `ls -l` | Тип | Пример |
|-----------------|-----|--------|
| `-` | Обычный файл | `/etc/hosts` |
| `d` | Директория | `/home/user` |
| `l` | Символическая ссылка | `/usr/bin/python -> python3` |
| `c` | Символьное устройство | `/dev/tty` |
| `b` | Блочное устройство | `/dev/sda` |
| `p` | Именованный канал (FIFO) | `/run/systemd/inhibit/...` |
| `s` | Unix-сокет | `/run/docker.sock` |

```bash
ls -la /dev    # посмотреть типы файлов
file myfile    # определить тип файла
```

## Inode (Индексный дескриптор)

**Inode** — структура данных на диске, хранящая метаданные файла.

### Что хранит inode

- Тип файла
- Права доступа (rwxrwxrwx)
- UID и GID владельца
- Размер файла
- Временны́е метки: atime (доступ), mtime (изменение), ctime (изменение метаданных)
- Количество жёстких ссылок
- Указатели на блоки данных на диске

### Чего НЕТ в inode

- **Имени файла** — оно хранится в директории (структура: имя → номер inode)

### Практика с inode

```bash
ls -li               # показать номера inode
stat filename        # полная информация об inode
df -i                # использование inode на разделах
find / -inum 12345   # найти файл по номеру inode
```

### Важно: исчерпание inode

Можно исчерпать inode при наличии свободного места на диске (много мелких файлов).

```bash
df -i     # проверить использование inode
# Если Use% = 100% — inode закончились
```

## Hard link и Soft link

### Hard link (жёсткая ссылка)

Hard link — дополнительное имя для того же inode. Оба имени равнозначны.

```bash
ln realFile hardLink
ls -li
# 2359720 -rw-r--r-- 2 user user 0 realFile
# 2359720 -rw-r--r-- 2 user user 0 hardLink
# ^ одинаковые номера inode, счётчик ссылок = 2
```

**Особенности:**
- Один и тот же inode → одинаковые метаданные
- Удаление одного имени не удаляет файл (данные удаляются, когда счётчик ссылок = 0)
- Только для файлов (не директорий)
- Только в пределах одной файловой системы/раздела

### Soft link (символическая ссылка)

Soft link — отдельный файл, содержащий путь к целевому файлу.

```bash
ln -s realFile softLink
ls -li
# 2359720 -rw-r--r-- 2 user user 0 realFile
# 2366763 lrwxrwxrwx 1 user user 8 softLink -> realFile
# ^ разные номера inode
```

**Особенности:**
- Свой inode, маленький размер (хранит путь)
- Может указывать на директории
- Работает между файловыми системами
- Если целевой файл удалён — ссылка «битая» (dangling symlink)
- Можно создавать на относительные и абсолютные пути

### Сравнительная таблица

| Параметр | Hard link | Soft link |
|----------|-----------|-----------|
| Inode | Общий с оригиналом | Собственный |
| Между разделами | Нет | Да |
| На директории | Нет | Да |
| При удалении цели | Файл доступен | Ссылка сломана |
| Тип в `ls -l` | `-` | `l` |

### Практическое применение

- **Hard link:** резервные копии без дублирования данных (`rsync --link-dest`), атомарные замены файлов
- **Soft link:** версионирование (`/usr/bin/python -> python3.11`), монтирование путей, конфиги

## Файловые дескрипторы

**Файловый дескриптор (FD)** — неотрицательное целое число, идентификатор открытого ресурса в процессе.

### Стандартные дескрипторы

| FD | Имя | Описание |
|----|-----|----------|
| 0 | stdin | Стандартный ввод |
| 1 | stdout | Стандартный вывод |
| 2 | stderr | Стандартный поток ошибок |

### Перенаправление

```bash
cmd > file          # stdout в файл
cmd 2> file         # stderr в файл
cmd > file 2>&1     # stdout и stderr в файл
cmd 2>&1 >/dev/null # stderr на экран, stdout в /dev/null
cmd &> file         # оба потока в файл (bash)

# Только stderr:
cmd 2>&1 >/dev/null | grep pattern
```

### Работа с дескрипторами

```bash
ls -la /proc/PID/fd    # открытые дескрипторы процесса
lsof -p PID            # открытые файлы процесса
ulimit -n              # лимит FD для пользователя
cat /proc/sys/fs/file-max  # системный лимит FD
```

## Монтирование: /etc/fstab

Файл `/etc/fstab` описывает, что и куда монтировать при загрузке.

### Формат

```
<device>  <mountpoint>  <fstype>  <options>  <dump>  <pass>
UUID=abc123  /home  ext4  defaults  0  2
/dev/sdb1    /data  xfs   defaults  0  0
tmpfs        /tmp   tmpfs defaults  0  0
```

| Поле | Описание |
|------|----------|
| device | Устройство: UUID, путь `/dev/sdX`, LABEL= |
| mountpoint | Точка монтирования |
| fstype | ext4, xfs, btrfs, tmpfs, nfs... |
| options | defaults, ro, noatime, noexec, nofail... |
| dump | 0 = не бэкапить командой dump |
| pass | Порядок fsck: 0=не проверять, 1=root, 2=остальные |

### Команды монтирования

```bash
mount -a               # примонтировать всё из fstab
mount /dev/sdb1 /mnt   # монтировать вручную
umount /mnt            # отмонтировать
df -h                  # список смонтированных ФС
lsblk                  # дерево блочных устройств
blkid                  # UUID и типы разделов
```

## RAID

**RAID (Redundant Array of Independent Disks)** — объединение дисков в логический массив для производительности и/или отказоустойчивости.

### Типы RAID

| RAID | Мин. дисков | Отказоустойчивость | Производительность | Использование |
|------|-------------|-------------------|-------------------|---------------|
| **RAID 0** | 2 | Нет (потеря 1 диска = потеря всего) | Чтение/запись × N | 100% |
| **RAID 1** | 2 | 1 диск | Чтение × N, запись × 1 | 50% |
| **RAID 5** | 3 | 1 диск | Хорошее чтение | (N-1)/N |
| **RAID 6** | 4 | **2 диска** | Немного хуже RAID 5 | (N-2)/N |
| **RAID 10** | 4 | До N/2 дисков | Очень высокая | 50% |

### Описание

- **RAID 0 (Stripe)** — данные разбиваются на полосы по дискам. Скорость максимальная, надёжность нулевая.
- **RAID 1 (Mirror)** — полное зеркало. Надёжность высокая, ёмкость минимальная.
- **RAID 5** — данные + одна паритетная информация распределены по дискам. Баланс между скоростью и надёжностью.
- **RAID 6** — два блока чётности. Переживёт выход из строя двух дисков одновременно.
- **RAID 10** — RAID 1 + RAID 0. Зеркальные пары, объединённые в страйп. Высокая скорость и надёжность.

### Software RAID в Linux (mdadm)

```bash
# Создание RAID 5
mdadm --create /dev/md0 --level=5 --raid-devices=3 /dev/sd{b,c,d}

# Статус массива
cat /proc/mdstat
mdadm --detail /dev/md0

# Добавить горячий резерв
mdadm /dev/md0 --add /dev/sde
```

## Популярные файловые системы

| ФС | Применение | Особенности |
|----|-----------|-------------|
| **ext4** | Универсальная, по умолчанию | Журналирование, проверенная |
| **xfs** | Большие файлы, высокая нагрузка | Хорошая параллельная запись |
| **btrfs** | SSD, снапшоты | COW, снапшоты, сжатие |
| **tmpfs** | `/tmp`, `/run` | В памяти, исчезает при перезагрузке |
| **nfs** | Сетевые хранилища | Монтирование по сети |

### Команды для работы с ФС

```bash
# Проверка и восстановление
fsck /dev/sda1         # проверить файловую систему (размонтированную!)

# Создание
mkfs.ext4 /dev/sdb1
mkfs.xfs /dev/sdc1

# Информация
tune2fs -l /dev/sda1   # метаданные ext4
xfs_info /dev/sda1     # метаданные xfs

# Расширение ext4 (онлайн)
resize2fs /dev/sda1
```
